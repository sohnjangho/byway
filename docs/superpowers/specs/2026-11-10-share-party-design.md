# 코스 공유와 드라이빙 파티 설계

## 1. 왜 하는가

- 기획서 1장이 "가는 길이 목적지가 됩니다. / 운전자들이 만든 드라이브 코스를 공유하고 함께 달리는 코스 플랫폼"으로 바뀐다 **[PM]**. 그러려면 운전자가 만든 코스가 다른 운전자에게 건너가고, 여러 대가 함께 달리는 장면이 실제로 동작해야 한다.
- PM은 이 두 기능을 기획서 제출(11-15 23:59) 전에 만들기로 정했다 **[PM]**. `docs/개발계획서.md`의 "공유는 PT 이후", "파티는 PT 필수 범위에서 뺀다"와 `2026-11-08-app-shell-server-design.md` 3장의 "드라이빙 파티는 범위 밖", 8장 일정(서버 11.21 이후)을 이 문서가 대체한다.
- 기획서 세션은 **11-14 낮까지** 동작 범위와 검증 결과(시험 수, 에뮬레이터 확인, 캡처)를 받아야 기획서 표기를 [계획]에서 [시험]·[실측]으로 바꿀 수 있다.

## 2. 목표

1. 운전자가 달린 길을 기록해 내 코스로 저장한다(부가 1).
2. 만든 사람이 공유 범위를 고른다. **전체**(둘러보기·랭킹에 노출) / **파티**(그 파티 멤버만) / **링크**(코드를 받은 사람만) **[PM]**.
3. 공유받은 코스도 내장 코스와 똑같이 "내비에 코스 입히기"와 구간 연출이 동작한다 **[PM]**.
4. 공유 코스에 완주 횟수를 보인다("차로 실제 달려 본 코스").
5. 같은 파티의 다른 차 위치를 주행 화면의 코스 위에, 프로필 그림을 원형으로 잘라 넣은 물방울 핀으로 보인다 **[PM]**.
6. 서버가 꺼져 있거나 닿지 않아도 내장 코스와 이미 받은 코스로 전체 흐름이 동작한다.

우선순위: 1~4(공유)가 먼저, 5(파티)가 다음이다 **[PM]**.

## 3. 하지 않는 것

- 공유 코스의 위성 장면·표지·한국 지도 위치 그림 생성(11-08 설계 7-2-1). 공유 코스는 이미 있는 대체 화면(코스 선 그림)으로 보인다 **[제안]**.
- 사진 올리기. 프로필은 기본 아바타에서 고른다 **[PM]**.
- QR, 폰 연동, 딥링크, 모바일 웹. 받아서 열 웹페이지가 없다 **[제안]**.
- 공개 HTTPS 배포, 클라우드. 서버는 gpu-wsl이다 **[PM]**.
- WebSocket, PostgreSQL, Docker. 2초 폴링과 SQLite 파일로 충분한 규모다 **[제안]**.
- 신고 처리 화면과 검수 흐름. 신고 버튼과 "신고 1건이면 숨김"만 넣는다(6-4) **[제안]**.
- 기기 토큰의 Keystore 암호화(11-08 설계 12장). 이번에는 앱 전용 저장소에 두고 PT 전에 붙인다 **[제안]**.
- 내비 거리 배율 통계 수집 **[제안]**.
- 파티 채팅·음성, 멤버끼리 경로 맞추기, 멤버 위치를 내비에 넣기.
- 코스 엔진(`core/engine`)과 내비 연동 동작 변경.

## 4. 실패로 보는 것

- 서버 장애나 느린 응답이 코스 안내·주행 화면을 멈추거나 늦춘다.
- 동의 버튼을 누르지 않았는데 위치·궤적이 기기 밖으로 나간다. 뒤로 가기나 빈 곳 터치를 동의로 본다.
- 동의를 철회했는데 서버에 위치가 남는다. 파티가 끝났는데 위치가 남는다.
- 주행 중(P단 외)에 파티 만들기·참여, 공유 범위 고르기, 코드 입력, 목록 조작이 보인다.
- 핀이 미끄러지듯 움직이는 등 주행 화면에 애니메이션이 생긴다.
- 화면·시험 데이터·시연에 실명, 연락처, 이메일, 소속이 나온다. 가상 멤버를 실제 사람처럼 보인다.
- 저장소에 테일넷 주소나 비밀 값이 들어간다. `ai.pleos.*`가 `platform/` 밖으로 나온다.
- 에뮬레이터에서 확인하지 않은 동작을 기획서 세션에 "동작함"으로 보고한다.

## 5. 제약

- `docs/제작가이드.md`를 따른다. 사건이 들어오고 명령이 나가며, 주행 규제는 `DriveGate`와 `screenFor` 한 곳에서 한다. 구조를 바꾸면 가이드를 먼저 고친다.
- Android View 코드, Kotlin 1.9.25, AGP 8.7.3, minSdk 28. 색·글자·치수는 토큰(`Palette.kt`)만 쓴다. 최소 12sp, 터치 76dp.
- Pleos 앱 심사 기준: 개인정보 항목·목적·보유 기간을 알리고, 동의 버튼만 동의로 본다. 철회하면 즉시 멈추고 지운다.
- AAR 분석 금지(Pleos 라이선스 3.4). 서브에이전트 지시서에도 적는다.
- 블라인드 심사. 프로필은 닉네임과 아바타 그림뿐이다.
- 에뮬레이터는 맥 1대뿐이고, 내비 자체 위치는 판교에 고정된다. 주행은 `adb emu geo fix`로 흘린다. 에뮬레이터를 쓸 때는 `tools/emulator-lock.sh`로 잠근다.
- gpu-wsl은 WSL 창이 닫히면 꺼진다(11-10 아침에도 꺼져 있었다). 서버도 같이 꺼진다.

## 6. 정한 것

### 6-1. 서버 **[PM: gpu-wsl]**

- 저장소의 `server/` Gradle 모듈. Kotlin + Ktor 2.3.x(Kotlin 1.9.25와 맞는 판)이고, `:core`를 그대로 가져다 코스 검사(`parseCourse`)와 거리 계산을 한 곳에만 둔다 **[제안]**. 비어 있는 `backend/`가 남아 있으면 지운다.
- 저장은 SQLite 파일 하나 **[제안]**. 파티 위치는 DB에 쓰지 않고 서버 메모리에만 두며 60초가 지나면 지운다.
- gpu-wsl에서 띄우고 테일넷으로만 연다. 11-10 실측: 맥 에뮬레이터에서 gpu-wsl 테일넷 IP로 HTTP 요청이 닿고, 테일넷 이름(`*.ts.net`)도 에뮬레이터 안에서 풀린다. 방식은 둘 중 하나다:
  - ① `tailscale serve` HTTPS 주소. 평문 허용이 필요 없다. gpu-wsl에서 serve 설정을 켜야 하는데, 이 세션의 실행은 권한 검사에서 막혔다 **[PM 결정 필요]**.
  - ② 테일넷 IP 평문 HTTP. 그 주소 하나만 평문을 허용하는 네트워크 보안 설정을 **빌드할 때 생성**해 저장소에 주소가 남지 않게 한다. 11-08 설계의 "release 평문 금지"는 제출용 빌드에서 지킨다(제출 APK에는 주소도 평문 허용도 없다). 테일넷 구간은 Tailscale이 암호화한다.
- 서버 주소는 저장소에 넣지 않는다. 빌드할 때 Gradle 속성(`local.properties` 등)으로 `BuildConfig`에 넣고, 없으면 빈 값으로 빌드되어 서버 기능이 "연결할 수 없음"으로 보인다 **[제안]**.
- `apk/*.apk`는 저장소에 커밋된다(`.gitignore`의 `!apk/*.apk`). 그래서 `apk/`에 두는 제출용 빌드는 반드시 주소 없이 만들고, 커밋 전에 APK 안에 테일넷 주소가 없는지 검사한다. 시연용 빌드는 `apk/` 밖에 둔다.
- 심사위원이 받는 APK는 테일넷에 닿지 않는다. 그래서 공유·파티 화면은 "공유 서버에 연결할 수 없습니다. 앱에 든 코스는 그대로 쓸 수 있습니다"로 보이고, 나머지 흐름은 그대로 동작한다. 공유·파티 동작은 영상과 PT로 보인다 **[제안]**.

### 6-2. 사용자 식별

- 로그인은 없다. 처음 서버에 닿을 때 익명 기기 토큰을 받아 앱 전용 저장소에 둔다(11-08 설계 7-2와 같음). 서버는 토큰의 해시만 저장한다.
- 설정에 "이 차의 내 데이터 지우기"를 둔다(11-08 설계 12장). 누르면 기기 안의 기록·받은 코스·프로필·토큰을 지운다. 서버에는 내가 올린 코스, 파티 멤버 정보, 위치의 삭제를 요청한다.
- 프로필은 닉네임(최대 10자)과 아바타 1개다. 아바타는 우리가 직접 그린 그림 8~12개 중에서 고른다 **[PM]**. 그림은 `tools/`의 생성 도구로 만들어 저작권 문제를 없앤다 **[제안]**. 프로필은 파티에 처음 들어갈 때 정하고 설정에서 바꾼다.

### 6-3. 코스 만들기(기록)

- 정차 중 내 코스 화면의 "길 기록하기"에서 시작한다. 시작 전에 동의 화면을 거친다. 이 화면에는 "위치를 1초마다 이 차에만 저장합니다. 공유하기 전에는 밖으로 나가지 않습니다"를 적는다.
- 기록은 이미 포그라운드 서비스인 `DriveService`가 돌린다. 내비가 앞에 나와도 기록이 멈추지 않아야 하기 때문이다. 코스 안내 주행과 동시에 돌지 않는다.
- 코드 위치 **[제안]**:
  - 자르기·구간 나누기·검사는 순수 로직이라 `core`의 `record/`에 둔다.
  - 화면은 `ui/record/`에 둔다. 기록 중 화면은 새 `Screen`으로 둔다. 지금 `screenFor`는 코스 없는 주행을 대기 화면으로 보내기 때문이다.
  - 가이드 5장 연결표의 `feature/record`는 `DriveFeature`(코스 주행 중 사건→명령) 모양이다. 기록은 코스 주행이 아니므로 기능 모듈로 두지 않는다.
  - 이 결정과 `server` 레인(`server/`)을 가이드 3·5·12장과 `tools/check-lane.sh`에 먼저 적는다.
- 주행 중 화면에는 한 줄(기록 중, 달린 거리)과 "기록 끝내기" 버튼 1개만 있다(11-08 설계 6-3).
- 끝내면 정차 화면에서 처리한다 **[제안]**.
  - 처음과 끝 500m를 자른다. 집 위치를 가리기 위해서이고, 11-08 설계의 300m보다 넓힌 값이다.
  - 남은 길이가 5km보다 짧으면 저장하지 않는다.
  - 경로를 단순화하고, 약 5km마다 구간을 나눠 "1구간", "2구간"처럼 이름 붙인다.
  - 이름과 코스 분위기를 운전자가 정한다. 분위기는 숲길·도시·물가 중 하나이고 모든 구간에 같이 들어간다. 차 안 연출(`AmbienceFeature`)과 음악(`MusicFeature`)은 구간의 분위기 값(`forest`·`city`·`river`)으로만 동작하므로, 이 값이 있어야 공유 코스에서도 구간 연출이 돈다. 구간마다 따로 고르는 화면은 두지 않는다.
  - 이름이 금칙어 목록에 걸리면 저장하지 않고 고쳐 달라고 한다.
- 저장은 앱 내부 저장소에 코스 형식 v2로 한다. `attribution`은 "에움길 운전자 기록"이다.

### 6-4. 공유

- 정차 중 내 코스에서 코스를 고르고 "공유"를 누르면, 범위 세 가지(전체/파티/링크) 중 하나를 고른다 **[PM]**.
- 이어서 동의 화면이 나온다. 무엇이 올라가는지(코스 경로·이름·닉네임), 누가 보는지, 언제 지워지는지를 적고, 동의 버튼을 눌러야 올라간다.
- **공유 전 검사** **[제안]**:
  - 6-3의 자르기·길이·금칙어 검사를 서버도 다시 한다.
  - 서버가 `parseCourse`와 기존 경유지 뽑기 규칙(허용 오차 1,200m)을 그대로 돌려 구간 분할을 확인한다. 기록한 길은 실제로 달린 길이라 경로 자체는 갈 수 있는 길이다.
  - 기획서 세션이 제안한 "내비 계산 거리 배율"은 재지 않는다. 재려면 운전자 내비에 경로를 올려야 하고, 에뮬레이터 내비는 판교에 고정이라 값도 맞지 않는다.
- **범위별 보이는 사람**
  - **전체:** 모든 사용자의 둘러보기·랭킹 목록에 "공유" 표시와 함께 뜬다. 코드도 붙는다.
  - **파티:** 공유할 때 고른 파티 하나의 현재 멤버만 본다. 코드는 붙지 않고, 서버가 멤버인지 확인한 뒤에만 내려준다. 그 파티가 지워지면 만든 사람만 본다.
  - **링크:** 6자리 코드를 받은 사람만 본다. 코드는 숫자 0·1과 글자 O·I를 뺀 대문자·숫자로 만든다. 코드는 정차 화면에 크게 보인다.
- 받는 쪽은 정차 중 둘러보기의 "코드로 받기"에 코드를 넣는다. 코스 코드와 파티 코드는 입력 칸이 다르다(파티 코드는 파티 화면에서 넣는다). 받은 코스는 앱 내부에 저장되어 내 코스의 "받은 코스"에 남는다. **주행은 언제나 기기 안의 파일로 한다**(11-08 설계 7-3).
- **신고** **[제안]**: 다른 사람이 만든 공유 코스에는 정차 화면에 "신고" 버튼이 있다. 신고가 1건이라도 들어오면 서버가 일단 숨기고, 개발자 확인용 목록에 남긴다(11-08 설계 7-2와 같음). 사용자 제작 콘텐츠의 신고는 Pleos 규정상 필요하다고 본 11-08 설계를 따른다.
- **"동의 전 요청 0건"의 범위:** 위치·궤적·닉네임·아바타가 담긴 요청을 말한다. 이런 정보가 없는 요청은 동의와 상관없이 나간다. 기기 토큰 발급, 공유 코스 목록, 코드로 받기, 완주 횟수 보내기가 그렇다.
- 만든 사람이 공유를 끄거나 지우면 서버 사본이 지워진다. 받은 사람의 목록에서는 다음 갱신 때 사라진다 **[제안]**.
- 공유 코스 화면 **[제안]**:
  - 표지·장면 그림이 없으므로, 카드와 홈 지도 칸은 코스 선 그림으로 대신한다. 둘러보기의 한국 지도에는 시작점 위치에 핀을 둔다.
  - 수치(거리·구간)는 경로로 계산한다. 고도·계절·시간 적합도처럼 근거가 없는 값은 비운다.
- 완주 횟수: 기존 `FinishRecorder` 지점에서 공유 코스 완주를 서버에 보낸다. 기기 식별자는 함께 저장하지 않는다. 공유 코스 카드와 홈에 "완주 N회"를 보인다.

### 6-5. 드라이빙 파티 **[PM: 한 번 달리기용 + 즐겨찾기]**

- **만들기**(정차 중): 코스 하나를 고르면 6자리 파티 코드가 생긴다. 파티 이름은 "<닉네임>의 파티"이고 바꿀 수 있다.
- **고를 수 있는 코스** **[제안]**:
  - 고를 수 있다: 내장 코스, 전체 공유 코스, 링크 공유 코스. 링크 코스는 코드를 가진 사람이 코드를 넘기는 것과 같다.
  - 내가 만들고 아직 공유하지 않은 코스: 고르면 6-4의 공유 동의 화면을 거쳐 "파티" 범위로 올린 뒤 파티를 만든다.
  - 다른 파티에서 받은 파티 범위 코스: 고를 수 없다. 원래 범위를 넘기 때문이다.
- **참여**(정차 중): 코드를 넣고, 프로필이 없으면 정한다. 위치 공유 동의 화면을 거친다. 파티 코스가 기기에 없으면 함께 받는다.
- **함께 달리기:** 파티 화면에서 "내비에 코스 입히기"를 누르면 보통 주행과 똑같이 시작한다. 위치 공유에 동의한 멤버만 2초마다 자기 위치를 보내고, 2초마다 다른 멤버 위치를 받는다.
- **표시:**
  - 주행 화면의 지도 칸(장면 그림이든 코스 선 그림이든)에 다른 멤버를 물방울 핀으로 찍는다. 핀 안에는 원형으로 자른 아바타가 들어간다 **[PM]**.
  - 주행 중에는 조작이 없다. 핀은 새 위치를 받으면 그 자리로 옮겨 다시 그리고, 미끄러지는 효과는 없다.
  - 30초 넘게 소식이 없는 멤버의 핀은 지운다 **[제안]**.
- **끝내기:** 파티를 만든 사람이 "파티 끝내기"를 누르거나 모든 멤버가 나가면 끝난다. 그 순간 서버 메모리의 위치를 모두 지운다.
- **즐겨찾기** **[제안: PM 답 "한 번 달리기용도 되고 즐겨찾기 기능도 됨"의 해석]**:
  - 멤버 누구나 파티에 별표를 달 수 있다. 끝난 파티 중 별표가 있는 것은 이름과 코드가 남는다. 별표한 멤버의 내 코스 "즐겨찾는 파티"에서 "다시 달리기"로 새 코스를 골라 같은 코드로 다시 연다.
  - 파티가 끝나면 별표하지 않은 멤버는 멤버에서 빠지고 닉네임·아바타도 지운다. 남는 것은 **스스로 별표한 멤버의 정보뿐**이다. 별표가 하나도 없는 파티는 파티까지 지운다.
  - 별표 버튼 옆에 "별표하면 이 파티가 끝나도 내 닉네임과 아바타가 이 파티에 남습니다. 별표를 끄거나 파티를 나가면 지웁니다"를 적는다. 별표 버튼을 누르는 것이 그 동의다.
- **파티 공유 코스:** 6-4의 "파티" 범위는 이 파티에 묶인다. 즐겨찾기로 남은 파티면 계속 보이고, 지워진 파티면 만든 사람만 본다.
- **동의와 삭제:**
  - 위치 공유는 파티마다 동의 버튼으로 켠다. 정차 중에는 파티 화면과 코스 중 정차 화면의 "위치 공유 끄기"로 언제든 철회한다.
  - 주행 중에는 버튼을 늘리지 않는다 **[제안]**. 이미 있는 "코스 끝내기"를 누르면 보내기가 멈추고 서버의 내 위치도 지운다. 주행 화면의 버튼 수 규칙(1개 + 코스 끝내기)을 지키기 위해서다.
  - 철회하면 바로 보내기를 멈추고, 서버에 내 위치 삭제를 요청한다. 서버는 그 즉시 메모리에서 지운다.
  - 파티를 나가면 멤버 정보도 지운다.
  - 동의 화면에는 항목(닉네임, 아바타, 위치), 목적, 보유 기간(파티가 끝날 때까지, 위치는 최대 60초), 거부 권리를 적는다.
- **시연용 가상 멤버** **[제안]**:
  - 서버를 시연 설정(환경 변수)으로 띄웠을 때만, 새 파티에 가상 멤버 2명이 들어온다. 이름은 "시연용 1", "시연용 2"다.
  - 실제 차의 위치가 오기 전에는 출발점에서 시속 약 60km로 코스를 따라 움직인다. 실제 차의 위치가 오면 그때부터 매번 실제 차의 코스 위 자리보다 약 1km 앞(시연용 1)과 약 1km 뒤(시연용 2)에 놓인다. 화면에 늘 함께 보이게 하려는 것이다.
  - 멤버 목록에는 "시연용 가상 멤버"라고 적고, 영상과 기획서에도 그렇게 밝힌다.

### 6-6. 주행 중 규칙

- 파티 만들기·참여·동의, 공유 범위 고르기, 코드 입력·표시, 프로필 고르기는 정차 화면에만 있다. `screenFor`의 기존 규칙을 따른다.
- 주행 중 새로 보이는 것은 다른 멤버의 핀과 기록 중 한 줄·버튼 1개뿐이다.
- 위치 송수신은 주행 중에도 돈다(개발계획서 계약 5 `SendLocation` 주행 중 허용과 같음).

### 6-7. 앱 연결

- 인터넷 권한을 더한다. 네트워크는 이미 있는 OkHttp로, 메인 스레드 밖에서 한다. 실패는 화면에 짧게 알리고 기록만 남긴다. 주행 중 실패는 알리지 않고 핀만 사라진다.
- 코스를 읽는 경로가 셋이 된다: 앱 자산, 내가 만든 코스, 받은 코스. `CourseCatalog` 앞에 출처를 합치는 층을 둔다. id가 겹치면 앱 자산이 우선이고, 서버가 붙이는 id는 겹치지 않는 형식이다.
- 둘러보기·랭킹의 공유 코스 목록은 정차 중 화면을 열 때 받아 저장해 두고, 받지 못하면 마지막 저장본을 보인다.

## 7. 확인 방법

- 시험: core(자르기, 구간 나누기, 검사, 코드 형식) · server(엔드포인트별, 범위별 접근 표, 삭제, 60초 만료, 철회 즉시 삭제, 가상 멤버 이동) · app(핀 자리 계산, 출처 합치기). 기존 시험 전부 다시 통과.
- 에뮬레이터(release 빌드):
  - 팔당 코스 일부를 `geo fix`로 흘려 기록한다. 저장, 세 범위 공유, 코드 받기까지 확인한다.
  - 다른 사용자의 공유는 두 번째 기기 토큰으로 서버에 직접 올려 흉내 낸다.
  - 받은 코스로 내비 경로 올림과 구간 연출을 확인한다.
  - 파티에서 가상 멤버 2명의 핀이 주행 화면에 보이는지 확인한다.
  - 철회 뒤 서버에 내 위치가 없는지 확인한다.
  - 서버를 끈 상태에서 앱 전체 흐름이 도는지 확인한다.
- 개인정보: 동의 전 위치·궤적·닉네임·아바타가 담긴 서버 요청 0건(로그), 키 문자열 0건(`grep`), 저장소와 `apk/`의 APK에 테일넷 주소 0건(`grep`, APK 안 문자열 검사). 신고 1건에 목록에서 숨는지, "내 데이터 지우기" 뒤 서버에 내 코스·멤버 정보가 없는지 확인.
- 캡처(2/3 창 기준, 주간): 기록 중, 공유 범위 고르기, 코드 화면, 둘러보기의 공유 카드, 파티 주행 화면의 핀.
