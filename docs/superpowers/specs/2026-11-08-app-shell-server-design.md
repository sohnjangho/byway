# 에움길 앱 새 화면 구조 이전 + 백엔드 구현 설계

> 작성 2026-11-08 · 기준 커밋 `652b9bd`(`feature/app-shell`) · 개발 위치 `gpu-wsl:~/projects/byway`
> 표기: **[PM]** PM이 정한 것 · **[제안]** 작성자가 정한 기본값(PM 미승인) · **[확인 필요]** 아직 모르는 것

## 1. 왜 하는가

- 앱은 옛 구조(상단 탭 5개: 홈·테마·랭킹·지역·내 코스)이고, 시안은 `design/screens`에서 새 구조로 바뀌었다. 지금 제출물(APK, 앱 영상)은 새 시안 이전 것이다.
- `backend/`는 비어 있다. PM은 기획서 작업과 별개로 앱을 프론트엔드와 백엔드까지 실제로 구현하길 원한다 **[PM]**. 그래서 `docs/개발계획서.md`의 "백엔드는 12.19 이후" 일정을 이 문서가 대체한다.
- 일정의 기준점은 제출 마감 11.15 23:59, 2차 PT 12.03~04(동작 앱 필수)다.

## 2. 목표

1. 앱이 시안의 구조와 모양으로 동작한다. 15개 코스를 실제 데이터로 보여 주고 "내비에 코스 입히기"로 기존 주행 흐름에 들어간다.
2. Ktor 서버가 코스 목록·상세·업로드, 완주 기록, 익명 디바이스 토큰을 제공하고 앱이 실제로 호출한다.
3. 운전자가 달린 길을 기록해 내 코스로 저장하고, 공유를 누르면 서버에 올라간다 **[PM]**.
4. 서버가 새 코스의 위성 장면과 지도 위치 자료를 만들어 내려주고, 앱은 내장 코스와 같은 화면으로 보여 준다 **[PM]**.
5. PT 전에 서버를 외부에 HTTPS로 배포한다 **[PM]**.
6. 서버가 꺼져 있거나 네트워크가 없어도 앱에 들어 있는 코스로 전체 흐름이 동작한다.

## 3. 하지 않는 것

- 코스 엔진, 내비 연동, 주행 규제의 동작 변경. `core/engine`, `DriveGate`, `screenFor`의 주행 규제는 그대로 쓴다.
- 드라이빙 파티, 날씨·TourAPI 프록시, 사진 첨부, 서킷: 이번 범위 밖이고 코스 기능 뒤에 별도로 설계한다 **[제안]**.
- 소셜 로그인, 댓글, 결제 **[제안]**. 업로드 코스의 필터링과 신고는 Pleos 규정상 필수이므로 범위에 넣는다(12장).
- 자율주행 구상 화면(`DriveAuto`), 시뮬레이터 개선.
- 브랜드명·기획서 수정.

## 4. 실패로 보는 것

- 서버 장애가 코스 안내에 영향을 준다.
- 주행 중(P단 외)에 목록·상세·지도 조작 화면이 보인다.
- 앱에 API 키가 들어간다. `ai.pleos.*`가 `platform/` 밖으로 나온다.
- 시안과 같아 보이지만 값이 가짜다. 근거 없는 수치·주변 정보를 표시한다.
- 에뮬레이터에서 확인하지 않고 동작한다고 보고한다.

## 5. 제약

- 저장소 규칙은 `docs/제작가이드.md`를 따른다(사건→명령, 레인, 토큰 생성 도구, SDK 격리). 구조 변경은 가이드를 먼저 고친다.
- UI는 현재처럼 Android View 코드로 짠다. Compose를 도입하지 않는다 **[제안]**: 기존 73개 파일, 시험, Kotlin 1.9.25와 맞춘다.
- 색·글자·치수는 `design/tokens.json` → `tools/make-theme.py` → `Palette.kt`만 쓴다.
- 창은 전체 2560×1210, 2/3 1700×1184, 1/3 841×1210 세 가지. 주야간은 시스템 모드를 따른다 **[PM]**.
- Pleos 에뮬레이터는 맥에만 있다(ARM 이미지). 빌드는 `gpu-wsl`, 실행 확인은 맥 AVD `Pleos_Connect`다. AAR 분석 금지(라이선스 3.4조).
- `gpu-wsl`은 WSL이 켜져 있어야 접속되고 서버도 돈다.

## 6. 프론트엔드

### 6-1. 메뉴와 화면

`Tab`을 4개로 바꾼다: 홈 · 둘러보기 · 랭킹 · 내 코스. 테마와 지역은 둘러보기의 칩으로 합친다. `TabBar`는 `.rail`에 해당하는 메뉴로 바꾼다. 전체·2/3 창은 왼쪽, 1/3 창은 위쪽 반투명이다 **[PM]**.

| 화면 | 시안 | 내용 |
|---|---|---|
| 홈 | `Main.dc.html` | 왼쪽 정보 칸(추천 문구, 코스 이름, 추천 표시, 요약, 수치 4개, 코스 주변 목록, "내비에 코스 입히기"), 오른쪽 위성 장면과 경로. 밀면 풍경 사진. 아래 코스 띠로 다른 코스 선택 |
| 둘러보기 | `Browse.dc.html` | 왼쪽 한국 지도, 오른쪽 카드. 카드나 지역 칩을 누르면 지도가 확대된다 |
| 랭킹 | `Ranking.dc.html` | 왼쪽 순위와 작은 한국 지도, 오른쪽 장면과 경로가 칸 없이 이어진다 |
| 내 코스 | `Me.dc.html` | 큰 지도에 내 코스 번호와 지명, 누르면 경로와 설명 |
| 주행·대기·요약 | `Drive`, `Waiting`, `Summary` | 동작은 그대로, 새 토큰과 배치만 적용 |

- 코스 상세(`Preview`)는 홈 화면이 그 역할을 맡으므로, 둘러보기·랭킹·내 코스에서 코스를 고르면 그 코스를 선택한 홈으로 간다 **[제안]**.
- 시안을 현재 상태로 확정하고 이전한다 **[제안]**. 이후 시안 변경은 추가 작업이다.

### 6-2. 데이터와 그림

- 장면 그림(`images/scene`, 약 3.8MB), 한국 지도(`images/atlas`), 경로 선·핀 좌표는 앱 자산으로 넣는다. `tools/make-screen-data.py`와 같은 원본에서 앱용 JSON을 만들어 시안과 앱의 값이 갈라지지 않게 한다.
- 지도 칸은 시안처럼 **미리 만든 위성 그림 + 벡터 경로 그리기**로 한다 **[제안]**: 네트워크가 필요 없고 시안과 똑같다. 기존 `CourseMapPane`(MapLibre)은 새 화면에서 쓰지 않는다.
- 분위기 효과는 정보 칸에만 넣고 지도·경로에는 넣지 않는다 **[PM]**. 날씨 입력이 없으므로 `moodFor`는 시간대·계절만으로 판단한다.
- 코스 주변 정보는 `tools/nearby.json`의 출처 있는 값만 쓴다. 영업 여부는 확인하지 못했으므로 표시하지 않는다.
- 사진·지도 출처는 화면과 앱 정보에 표시한다(`sceneryCredit`, EOX, OSM).

### 6-3. 코스 만들기 (부가 1) **[PM]**

- `feature/record` 모듈 + `app/.../ui/record/`. 기록 시작은 내 코스 화면(정차 중)에서 한다. 주행 중 표시는 한 줄과 "기록 끝내기" 버튼 1개뿐이다.
- `FusedLocation` 위치를 받아 궤적을 쌓는다. 코스 안내 주행과 동시에 돌지 않으며, 기록 전용 주행 상태가 필요하면 contract 레인에서 먼저 사건을 정한다.
- 끝내면 정차 상태에서 이름을 넣고 내 코스로 저장한다. 앱 내부 저장소에 코스 형식 v2로 저장하며 구간은 1개, `attribution`은 "운전자 직접 기록"으로 채운다 **[제안]**. 짧은 기록(2km 미만)은 저장하지 않는다 **[제안]**.
- 집 위치 노출을 막기 위해 시작과 끝 300m를 잘라 저장하고 올린다 **[제안]**.
- **자동 업로드는 없다.** 정차 중 "공유" 버튼과 명시적 동의 화면을 지나야 올라간다. 삭제하면 서버 사본도 지운다.

## 7. 백엔드

### 7-1. 구조

- 저장소 `server/` Gradle 모듈, Kotlin + Ktor. `:core`의 `parseCourse`로 업로드를 검증해 코스 형식을 한 곳에만 둔다 **[제안]**. 비어 있는 `backend/`는 지운다.
- PostgreSQL. 코스 본문은 jsonb. `docker compose`로 `gpu-wsl`에서 서버와 DB를 실행한다 **[제안]**.
- 비밀 값은 환경 변수. 저장소에 `.env`를 넣지 않는다.

### 7-2. API

| 메서드·경로 | 내용 |
|---|---|
| `POST /v1/devices` | 익명 디바이스 토큰 발급. 이후 요청은 `Authorization: Bearer` |
| `GET /v1/courses?region=&theme=&since=` | 코스 요약 목록 |
| `GET /v1/courses/{id}` | 코스 전체 JSON |
| `POST /v1/courses` | 코스 업로드. id는 서버가 새로 붙인다. `parseCourse` 실패는 400 |
| `DELETE /v1/courses/{id}` | 올린 기기만 삭제 가능 |
| `GET /v1/courses/{id}/assets` | 장면 자료 상태와 파일 주소. `pending`, `ready`, `failed` |
| `POST /v1/courses/{id}/runs` | 완주 기록 `{finishedAt, meters}`. 디바이스 식별자를 저장하지 않는다 |

테이블: `device(id, token_hash, created_at)`, `course(id, schema_version, name, region, themes, body jsonb, author_device_id, visibility, assets_state, created_at, updated_at)`, `run(id, course_id, meters, finished_at)`. 서버 시작 시 앱 자산의 15개 코스를 넣는다. 업로드 코스는 금칙어 필터를 통과해야 공개되고, `POST /v1/courses/{id}/reports`로 신고를 받으며 신고 1건이면 일단 숨긴다 **[제안]**. 개발자 확인용 신고 목록을 둔다.

`followedRatio`는 넣지 않는다 **[제안]**: 계산하는 코드가 없고 엔진을 고치거나 근거 약한 값을 만들어야 한다.

### 7-2-1. 장면 자료 생성 **[PM]**

- `tools/`의 Python 도구(`make-scenes.py`, `make-covers.py`, `make-atlas.py` 계열)를 서버 작업자 컨테이너에서 코스 1개 단위로 돌도록 묶는다. 도구가 시안 전체를 전제로 한 부분만 코스 단위 입력으로 바꾼다.
- 업로드되면 작업 대기열에 넣고 주간·야간 장면, 경로 선 좌표, 한국 지도 위 위치, 수치, 커버를 만든다. 결과는 파일 저장소(개발 중 Docker 볼륨)에 두고 API로 내려준다.
- 앱은 `ready`인 자료를 내려받아 저장한 뒤 내장 코스와 같은 화면으로 보여 준다. `pending`·`failed`이면 경로 선 그림 카드로 대신한다.
- 위성 타일은 **EOX 2016판만** 쓴다(CC BY 4.0, 2026-11-08 EOX FAQ 확인). 2017년 이후 판은 비상업(NC)이거나 유료라 쓰지 않는다. 장면을 그린 결과물만 내려주고 원본 타일을 그대로 제공하지 않으며, 그림이 보이는 모든 곳에 출처를 표시한다. SLA가 없고 공정 사용 조건이 있어 받은 타일은 서버에 캐시하고 요청 속도를 제한한다.
- 번들 15개와 id가 겹치면 앱 내장본이 우선이다. 서버가 붙이는 id는 겹치지 않는다.

### 7-3. 앱 연결

- 두 번째 경로가 생기므로 `CourseSource`를 추출한다(자산·원격 저장본). 가이드 5장 규칙에 맞는다.
- 정차 중 앱 시작 때 백그라운드로 목록을 받아 앱 내부 저장소에 저장하고, 다음 목록 갱신 때 반영한다. **주행은 언제나 로컬 파일로 한다.**
- 네트워크는 기존 OkHttp를 쓴다. 호출은 메인 스레드 밖에서 하고 실패는 기록만 남긴다. 완주 기록은 실패하면 버린다 **[제안]**.
- 서버 주소는 `BuildConfig` 한 곳. 개발 중 주소는 `http://100.83.190.98:<포트>`이고 debug 빌드만 평문 HTTP를 허용한다. 맥 에뮬레이터에서 이 주소에 닿는지는 **[확인 필요]**이며 구현 첫 단계에서 잰다.
- `DriveEvent`·`DriveCommand`에 새 항목이 필요하면 contract 레인 규칙을 따른다. 완주 기록 전송은 이미 있는 `FinishRecorder` 지점에 붙인다.

### 7-4. 배포 **[PM]**

- 11.15 제출 APK는 서버 주소를 비워 내장 코스만으로 동작한다 **[제안]**. 공모전 규정대로 **실행 가능한 release 빌드**를 `apk/팀명_앱이름_release.apk`로 올리고(서명 키는 저장소 밖), README에 앱 이름·한 줄 소개, 실행 방법, 테스트 환경, APK 위치를 쓴다. 1차 제출물은 PT 전까지 고도화가 허용된다.
- PT 빌드는 외부 HTTPS 서버를 쓴다. 호스팅 업체와 예산은 배포 단계 전에 PM이 정한다(개발계획서 가정 월 1~2만 원대, 실제 요금 **[확인 필요]**).
- release 빌드는 평문 HTTP를 허용하지 않는다. 서버 장애 시 내장 코스로 이어 간다.

## 8. 순서

**제출본 먼저, 서버는 그 뒤에 쌓는다 [제안].** 세 선택 모두 범위가 커서 11.15까지 전부 끝난다고 보지 않는다.

| 단계 | 내용 | 목표 시점 |
|---|---|---|
| 1 | 앱 자산 도구 + 메뉴 + 홈 (창 3종, 주야간) → 맥 에뮬레이터 확인 | 11.11 |
| 2 | 둘러보기·랭킹·내 코스, 주행·대기·요약 재배치 → 전체 흐름 확인 | 11.13 |
| 3 | **제출용 APK·앱 시연 영상 후보**. 태그를 달고 이후 개발과 분리 | 11.14 |
| 4 | 서버 + DB + 업로드·완주 API + 시험 | 11.21 |
| 5 | 코스 만들기(궤적 기록, 저장, 공유) | 11.25 |
| 6 | 장면 자료 생성 작업자, 앱의 내려받기와 표시 | 11.28 |
| 7 | 외부 HTTPS 배포, 앱 연결 최종, 서버 끔·켬 시험 | 11.30 |
| 8 | 전체 재검증, PT 빌드 동결, PR 보고서 | 12.02 |

11.14까지 단계 1~2가 끝나지 않으면 현재 APK를 내고 새 구조는 시안·영상으로 설명한다.

## 9. 완료 기준

- `./gradlew :core:test :app:testDebugUnitTest :feature:*:test :server:test` 통과 로그.
- `tools/check-lane.sh`, `grep`으로 `ai.pleos` 격리와 키 문자열 0건.
- 맥 에뮬레이터에서 FHD가 아닌 실제 앱 창 3종, 주야간 캡처를 눈으로 확인.
- 코스 선택 → 내비 입히기 → 구간 안내 → 완주 요약 → 완주 기록이 DB에 저장됨을 확인.
- 궤적 기록 → 저장 → 공유 동의 → 업로드 → 장면 자료 `ready` → 앱에서 내장 코스와 같은 화면 표시 → 주행까지 확인.
- 공유하지 않은 기록은 서버 요청이 0건임을 확인. 삭제 시 서버 사본이 사라짐을 확인.
- PT 빌드가 외부 HTTPS 주소로 같은 흐름을 통과.
- 서버를 내린 상태에서 같은 흐름이 끝까지 동작.
- 기어 P→D 전환 시 주행·대기 화면으로 바뀌고 메뉴가 사라짐.
